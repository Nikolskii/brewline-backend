## Назначение

Backend Brewline — REST API и real-time поток статусов заказов. Это источник истины контракта:

`zod-схемы → openapi/openapi.yaml → @brewline/api-types → фронты`.

`openapi/openapi.yaml` генерируется и коммитится. Не редактируй его вручную: используй `npm run gen:spec`.

## Изменение API

1. Сначала измени zod-схемы в `src/contract/schemas.ts` и маршруты генератора при необходимости.
2. Запусти `npm run gen:spec` и закоммить обновлённую спецификацию.
3. Подними версию `packages/api-types/package.json` по SemVer.
4. После публикации тега `api-types-v<версия>` фронты смогут получить новую версию пакета.

Схемы и контракт изменяются до бизнес-логики, чтобы не блокировать фронтенды.

## Стек и границы

- Node.js, Express, TypeScript strict, MongoDB, SSE-снапшоты очереди.
- В текущем инкременте добавляются аутентификация бариста и CORS для фронтов на отдельных origin; чтение очереди остаётся публичным, `PATCH` защищён.
- Локальный dev-стек: `docker compose up` в этом репозитории.

## Безопасность

Не коммить `.env`, строки подключения с паролями, токены и ключи. Используй `.env.example` и плейсхолдеры.
